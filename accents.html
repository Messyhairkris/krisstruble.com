Chapter VI · Tools / Automation

Accent Picker

My office-mate Jasper needed to type a new employee’s name correctly, but there was no convenient way to enter the accents. We found a workaround, but it was awkward enough that I started wondering if I could make a better one.

I built it in AutoHotkey, a Windows automation tool I have used for years to make small tasks run more smoothly.

  • Clear writing
  • Technical curiosity
  • Tools for the team

The Accent Picker

The finished tool uses a caret as a shortcut. Type ^ followed by a letter, such as ^e, and a small window appears with the available diacritics:

^e→ éèêëēėę

You can move through the choices with the keyboard or select one with the button, and then continue typing normally.

Getting that simple interaction to work meant solving a few less-visible problems too. The picker needed to respond only to the intended letters and open centered on the screen you’re working on, even across multiple monitors.

I compiled the AutoHotkey script into an executable and made an icon so Jasper could install it without needing AutoHotkey or the source code.

Then I found the next problem

When I showed Jasper the finished program on my computer, I realized that simply giving him the executable wasn’t enough. The tool needed to start automatically when Windows started, and I didn’t want him to have to figure out where to put files or how to configure it.

So I continued to prototype and made a second program.

The Installer Creator

The installer takes a project folder and sets it up for the user: program files go where they belong, the application is added to the Windows startup folder, and shortcuts are created on the desktop and Start menu.

It also generates an uninstaller that removes what the installer added.

That turned a tool I had built for one coworker into something I could actually hand to someone else and expect them to use.

Why AutoHotkey

AutoHotkey is particularly useful to me for this kind of work because it speaks Windows natively and lets me prototype an idea quickly. The finished programs are not trying to compete with polished commercial software. They are functional tools built to solve a specific problem.

For me, that is often the important part: get the idea working, use it, find the next problem, and improve the tool.
